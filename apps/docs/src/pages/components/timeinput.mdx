## Use cases

### Defining maintenance window boundaries

Use TimeInput when a user defines the start and end of a same-day window, such as a maintenance window from 02:15 to 03:45. Collect hours and minutes only; a date or seconds would add unnecessary precision.

### Setting report delivery times

Use TimeInput when a user chooses the time of day a recurring action should run, such as when a daily report is sent. A quarter-hour `minuteStep` keeps the choices manageable, for example 8:00 AM, 8:15 AM, and 8:30 AM.

### Constraining selection to a fixed range

Use TimeInput when valid times must fall within a fixed range, such as booking an appointment between 8:00 AM and 6:00 PM and use 15-minute or 30-minute intervals to keep the available choices manageable. Validate out-of-range values before submission so the user cannot proceed with an invalid time.

## Behaviors and States

### Interactive states

- TimeInput presents editable sections for hours and minutes, with seconds available when `showSeconds` is enabled.
- Focus moves between the active time sections as the value is edited, and the time popup provides an alternative way to choose a value.
- The `format` prop controls whether the input uses a 12-hour or 24-hour arrangement. A 12-hour arrangement includes a meridiem section (AM/PM).
- The `minuteStep` prop controls the interval used for minute selection.

### Application states

- Set `disabled` when the time cannot be entered or changed. The input and its selection interactions do not accept edits while disabled.
- Set `readOnly` when the value should remain visible and focusable without allowing edits.
- Use `defaultValue` for an uncontrolled initial value and `value` with `onChange` for a controlled value.

### General behaviors

- When `format` is not provided, the component selects the 12-hour or 24-hour convention from the browser's default locale.
- When `minuteStep` is not provided, the component uses a one-minute interval.

## Content Guidelines

- When customizing `messages`, preserve clear labels for the input, active section, hours, minutes, seconds, and meridiem (AM/PM) values.
- Provide an `invalidTime` message that explains that the entered time is invalid.
- Provide a `currentValue` message that identifies the committed hour, minute, second, and meridiem values when those sections are complete.

## Accessibility

- Support focus movement between the time sections so keyboard and assistive technology users can identify and edit each portion of the value.
- Use `messages` to provide localized labels and announcements for the input, active section, section values, and time-selection controls.
