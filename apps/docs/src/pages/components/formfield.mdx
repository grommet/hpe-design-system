## Use cases

### Entering a labeled form value

Use FormField to give an input a clear, persistent label so users understand what to enter. Associate the label with its input using matching `htmlFor` and `id` values.

### Validating a named form field

Use a named FormField inside a Form to check that an entered value meets your requirements before submission. Define validation rules with `validate` and use `validateOn` to control when they run. Provide clear guidance on the expected input and actionable error messages so users can correct invalid values.

## Behaviors and states

### Interactive states

- FormField tracks focus within the field and applies focus styling; focus is not a separate field control.
- Recognized Grommet input children can receive field-managed focus styling when they have not explicitly configured their own `plain` or `focusIndicator` properties. Do not assume the same behavior for arbitrary custom children.

### Application states

- **Disabled:** `disabled` disables an input created internally by FormField, but is not automatically copied to every explicitly supplied child. Configure an explicit child input's disabled state as needed.
- **Error:** `error` displays a field-specific message and marks the field as invalid. 

### General behaviors

- Use `validate` within `Form` and supply a field `name`. Set `validateOn` to `blur`, `change`, or `submit` when the validation timing needs to be explicit.
- For blur validation, moving focus into a related input dropdown does not immediately count as leaving the field.
- `required` marks the field as required and displays its indicator. Use `required={{ indicator: false }}` to suppress the visual indicator without removing required semantics.

#### Composition

- **Child control:** Provide and configure the input as a child of FormField. This gives you direct control over its props and composition. Manage its value yourself outside a `Form`; inside a Grommet `Form`, give the child input a `name` to connect it to form values and submission.
- **FormField-created control:** Inside a Grommet `Form`, use the `component` and `name` properties when you want FormField to create the input and connect it to form-managed values and submission. If no child or `component` is provided, FormField uses its TextInput fallback.

## Content guidelines

- Keep field labels short and descriptive.
- Use `help` text to explain how to complete the field.
- Use `error` text to describe an issue with the current value.
- Use `info` text for additional context about the field value.

## Accessibility

Associate each field label with its input. Set `htmlFor` on FormField to match the input's `id`. For recognized Select or SelectMultiple children whose `id` matches `htmlFor`, FormField appends `__input` when needed to target the internal input.

FormField does not define a separate keyboard interaction pattern. The contained input provides its keyboard behavior; custom inputs must provide their own keyboard support and accessible semantics.

| Attribute          | Value                              | Condition                                                                                                                                                                                  |
| ------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `aria-invalid`     | `true`                             | A field error is present on a recognized Grommet input child or an internally created input.                                                                                               |
| `aria-describedby` | Generated error-message identifier | An error and `htmlFor` are present; FormField links recognized Grommet input children or its internally created input to the error message and preserves existing description identifiers. |
| `aria-hidden`      | `true`                             | When the built-in required indicator is displayed, the visual asterisk is hidden from assistive technology and accompanied by visually hidden “required” text.                                |

Do not assume that FormField automatically associates help or informational text with every input. Provide and verify any additional description associations required by the chosen input. Custom child components do not receive the same automatic error associations as recognized Grommet inputs.

Do not assume that `required` automatically sets `aria-required` on every child. Verify required semantics on the actual input, especially when the visual indicator is suppressed.
