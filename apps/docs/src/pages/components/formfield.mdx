## Use cases

### Entering a labeled input

Use FormField to give an input a clear, persistent label so users understand what to enter. Associate the label with its input using matching `htmlFor` and `id` values.

<Example height={{ min: 'small' }} pad="medium">

### Validating a named input

Use a named FormField inside a Form to check that an entered value meets requirements before submission. Define validation rules with `validate` and use `validateOn` to control when they run. Provide clear guidance on the expected input and actionable error messages so users can correct invalid values.

## Behaviors and states

### Interactive states

- FormField tracks focus within the field and applies focus styling; focus is not a separate field control.
- Recognized Grommet input children can receive field-managed focus styling when they have not explicitly configured their own `plain` or `focusIndicator` properties. Verify focus styling behavior for arbitrary custom children.

### Application states

- **Disabled:** `disabled` disables an input created internally by FormField, but is not automatically copied to every explicitly supplied child. Configure an explicit child input's disabled state as needed.
- **Error:** `error` displays a field-specific message and marks the field as invalid. 

### General behaviors

- Use `validate` within `Form` and supply a field `name`. Set `validateOn` to `blur`, `change`, or `submit` when the validation timing needs to be explicit.
- For blur validation, moving focus into a related input dropdown does not immediately count as leaving the field.
- `required` marks the field as required and displays its indicator. Use `required={{ indicator: false }}` to suppress the visual indicator without removing required semantics.

#### Composition

- **Child control:** Provide and configure the input as a child of FormField for direct control over its props and composition. Manage its value outside a `Form`; inside a Grommet `Form`, give the child input a `name` to connect it to form values and submission.

  ```jsx
  <Form>
    <FormField label="Email" name="email" htmlFor="email" required>
      <TextInput
        id="email"
        name="email"
        type="email"
        placeholder="name@example.com"
      />
    </FormField>
  </Form>
  ```

- **FormField-created control:** Inside a Grommet `Form`, use the `component` and `name` properties to have FormField create the input and connect it to form-managed values and submission. If no child or `component` is provided, FormField uses its `TextInput` fallback.

  ```jsx
  <Form>
    <FormField
      label="Email"
      name="email"
      htmlFor="email"
      id="email"
      component={TextInput}
      type="email"
      placeholder="name@example.com"
      required
    />
  </Form>
  ```

## Content guidelines

- Keep field labels short and descriptive.
- Use `help` text to explain how to complete the field.
- Use `error` text to identify unmet requirements or other issues with the current value and explain how to correct them.
- Use `info` text to explain input requirements or provide information about the current value or selection, without indicating an error.
  - For input requirements, use guidance such as "Use at least 12 characters, including a number and a symbol."
  - For selection-related information, use feedback such as "Version 8.1 selected" with a "See version details" link.

## Accessibility

- Associate each field label with its input by setting `htmlFor` on FormField to match the input's `id`.
- For recognized `Select` or `SelectMultiple` children whose `id` matches `htmlFor`, FormField appends `__input` when needed to target the internal input.

FormField does not define a separate keyboard interaction pattern. The contained input provides its keyboard behavior; ensure custom inputs provide their own keyboard support and accessible semantics.

| Attribute          | Value                              | Condition                                                                                                                                                                                  |
| ------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `aria-invalid`     | `true`                             | A field error is present on a recognized Grommet input child or an internally created input.                                                                                               |
| `aria-describedby` | Generated error-message identifier | An error and `htmlFor` are present; FormField links recognized Grommet input children or its internally created input to the error message and preserves existing description identifiers. |
| `aria-hidden`      | `true`                             | The built-in required indicator is displayed. The visual asterisk is hidden from assistive technology and paired with visually hidden “required” text.                                |

- Associate help and informational text with the input, using `aria-describedby` where appropriate, and verify the association on the chosen input. FormField does not automatically associate this text with every input.
- When informational text changes in response to input or selection, make relevant feedback available to assistive technology without moving focus. Use an appropriate live region when an announcement is needed; FormField does not automatically announce `info` updates.
- Verify error associations on custom child components — only recognized Grommet inputs receive automatic error associations.
- Verify required semantics on the actual input, especially when the visual indicator is suppressed — `required` does not automatically set `aria-required` on every child.
