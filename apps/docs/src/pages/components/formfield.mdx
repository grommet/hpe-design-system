## Use cases

### Entering a labeled form value

Use FormField inside a `Form` to capture a project name before saving project settings. Provide a `TextInput` labeled “Project name,” with “Infrastructure monitoring” as representative entered content. Associate the label with the input using matching `htmlFor` and `id` values. As the user types, the input displays the updated project name.

<Example height={{ min: 'small' }} pad="medium">
  <FormFieldEnteringLabeledFormValueExample />
</Example>

### Correcting a field value

Use FormField inside a contact-details `Form` to explain an email-address issue next to the affected `TextInput`. Label the field “Contact email” and use “operations.example.com” as an illustrative invalid entry. Provide help text explaining the expected address format and error text identifying the missing “@” character. When the user corrects the value to “operations@example.com” and validation succeeds, clear the error while retaining the help text.

<Example height={{ min: 'medium' }} pad="medium">
  <FormFieldCorrectingFieldValueExample />
</Example>

### Validating a named form field

Use a named FormField inside a `Form` when a project code must meet a defined format before submission. Label the field “Project code” and describe an illustrative format of three uppercase letters followed by three digits, such as “OPS123.” Configure the field's `validate` rule and explicitly choose `validateOn="submit"` for this scenario. Submitting “OPS12” presents a field error; correcting the value to “OPS123” and submitting again allows the form's successful submission path.

## Behaviors and states

### Interactive states

- FormField tracks focus within the field and applies the focus treatment configured by the theme. The visible treatment depends on the border and focus configuration; it is not a separate field control.
- Recognized Grommet input children can receive field-managed focus styling when they have not explicitly configured their own `plain` or `focusIndicator` properties. Do not assume the same behavior for arbitrary custom children.

### Application states

- **Disabled:** `disabled` changes the field's theme-dependent presentation. It is passed to an input created internally by FormField, but is not automatically copied to every explicitly supplied child. Configure an explicit child input's disabled state as needed.
- **Error:** `error` displays a field-specific message and can affect border or background styling according to the theme. Help, error, and informational text are separate message regions; an error does not inherently replace help text.

### General behaviors

- Use `validate` within `Form` and supply a field `name`. Set `validateOn` to `blur`, `change`, or `submit` when the validation timing needs to be explicit.
- For blur validation, moving focus into a related input dropdown does not immediately count as leaving the field.
- `required` controls the required-field configuration. The visible indicator depends on the theme; the object form with `indicator: false` suppresses that indicator.
- Within `Form`, FormField can create an input when no child is supplied, using `component` or its internal TextInput fallback. Explicit children remain responsible for their own input configuration.

## Content guidelines

- Keep field labels short and descriptive.
- Use `help` text to explain how to complete the field.
- Use `error` text to describe an issue with the current value.
- Use `info` text for additional context about the field value.

## Accessibility

Associate each field label with its input. Set `htmlFor` on FormField to match the input's `id`. For recognized Select or SelectMultiple children whose `id` matches `htmlFor`, FormField appends `__input` when needed to target the internal input.

FormField does not define a separate keyboard interaction pattern. The contained input provides its keyboard behavior; custom inputs must provide their own keyboard support and accessible semantics.

| Attribute          | Value                              | Condition                                                                                                                                                                                  |
| ------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `aria-invalid`     | `true`                             | A field error is present on a recognized Grommet input child or an internally created input.                                                                                               |
| `aria-describedby` | Generated error-message identifier | An error and `htmlFor` are present; FormField links recognized Grommet input children or its internally created input to the error message and preserves existing description identifiers. |
| `aria-hidden`      | `true`                             | The theme uses the built-in boolean required indicator; the visual asterisk is hidden from assistive technology and accompanied by visually hidden “required” text.                        |

Do not assume that FormField automatically associates help or informational text with every input. Provide and verify any additional description associations required by the chosen input. Custom child components do not receive the same automatic error associations as recognized Grommet inputs.

Do not assume that `required` automatically sets `aria-required` on every child. Verify required semantics on the actual input, especially when the visual indicator is suppressed.
